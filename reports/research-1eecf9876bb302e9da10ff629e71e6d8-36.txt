DECISION
Do not promote the runtime candidate. It repairs the tested small-history and
height-shrink count failures, but does not supply a correct complete resize
coordinate contract. Height growth still detaches an actual picture from text.
This failure also occurs in the shipping control: it is not evidence that the
candidate introduced a growth regression. No performance sessions were run and
no executable was selected or replaced. No Ghostty superiority or championship
is established. Keep two clearly named defect-characterization tests, NOT tests
asserting correct behavior. They deliberately record broken behavior and must be
removed/replaced when a real fix lands.

NEW CONCRETE RESULTS (BEYOND ITERATION 35)
1. Inactive-primary height shrink loses movement in the shipping runtime even
   with sufficient history. On a 4x10 primary terminal, 24 CRLF records produce
   base 21. Mark row 2, put the cursor at row 3, enter alternate screen, shrink
   to height 2, and return. The marker moves to primary row 0, so its absolute
   coordinate requires base 23, but the engine reports 21. The selection observer
   was removed at the screen switch. The active-only shrink repair also misses
   these pushes; resizing the primary grid while inactive must be included.
2. Height growth detaches an actual picture from its text in SHIPPING CONTROL.
   On 4x10, 12 CRLF records give base 9 and retained history. Pump a real picture
   onto row 0 with marker M. Resize to 6x10 using Session's reflow/set-scrolled
   sequence. Text M is now at row 2, but picture row remains 0. Base remains 9,
   and take_reflow() returns None. This is not merely an assertion about a
   counter: the end-to-end intake placement diagnostic reproduces the mismatch.
   Primary absolute marker coordinate changes 9 -> 11 with no mapping emitted.
   A monotonic output counter cannot alone describe history retrieved on growth.
3. The sweep's documentation names an obsolete mutation probe. GLASS_RUN_PROBE=5
   passes BOTH 200 and 12,800 streams. The implementation explicitly makes
   probes 3..99 inert. GLASS_RUN_PROBE=100 FAILS the exact sweep at seed 1 round 0
   (cell divergence, one test failed). Thus the positive sweep is genuinely
   exercised, but probe 5 must not be cited as mutation-sensitivity evidence.
   No shipping source/comment was silently changed to hide this finding.

PREDECLARED PRIMARY EXPERIMENT
protocol.json was written before runtime edits. Baseline sources, selected ELF,
tracked evidence and docs were hashed first. The initial candidate used Term's
monotonic primary movement counter (output scrolls and actual ED2 pushes), with
height-only shrink increments max(cursor_row+1-new_height,0). The counter excludes
width reflow because the existing reflow mapping owns that coordinate change.
The first repair inspected only the active primary. Its new inactive oracle
failed 696/1,392 scenarios; the retained v2 inspects the actual primary grid,
whether active or inactive, BEFORE grid resize. This is a diagnostic refinement,
not a post-performance rescue: the performance gate never opened.

EVIDENCE VALIDATION
verify.py recomputes matrix identities/completeness and independent expected
vectors. It rejects duplicate, absent or unknown cases, false match flags,
inconsistent observations, wrong outcomes, wrong environments, missing exact
single-test executions, zero-stream sweeps, changed source scope or changed
shipping ELF/evidence. Numeric case rows are also hash-bound to frozen measured
observations: merely preserving the number of wrong control cases is not enough.
The first negative test exposed exactly that checker weakness; it is retained
in python-tests-v1-failure.log and verify-v1.py.txt, then repaired.
Four Python tests pass; 56 rehashed semantic/receipt corruptions rejected.
These finite negative tests are not exhaustive/adversarial evidence security.
