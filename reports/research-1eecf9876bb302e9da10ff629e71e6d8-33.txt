GLASS EXACT TERMINAL CORPUS BRIDGE — ITERATION 33 (2026-11-03)

RESULT / RETAINED CODE
A materially distinct benchmark-path improvement, not another rejected decoder
or handler optimization. Added bench/export-tput-corpus.py and an opt-in
GLASS_BENCH_CORPUS loader to the existing cfg(test) speed module. Existing
production terminal/parser source is unchanged. The exporter executes the
unchanged trusted tput.py generator, not an approximate RNG port. Fixed payload
filenames and manifest-last publication avoid partial-completion ambiguity;
loader checks geometry, expected six names and lengths, refuses rescaling.
The loader does NOT check SHA256; external runners must do so before/after use.

CONCRETE NEW FINDING
The generated Rust benchmark corpus is not byte-identical to the actual Python
terminal corpus in five of six workloads. ASCII and scroll-region differ even
though lengths match. Python minus Rust byte counts: Unicode -12, truecolor
-2382, cursor-motion -400. Only deterministic TUI is identical. Rust uses
xorshift and consumes extra random state generating its extra ASCII-LF corpus;
Python uses random.Random(7). An independent top-level runpy execution of the
unchanged terminal script, mocking only geometry/waiting and the stop before
terminal-mode change, matches every exported payload byte-for-byte. This check
uses no AST extraction and performs no terminal I/O.

FROZEN EXPERIMENT
Exactly 24 sequential sessions / 12 alternating generated/exact pairs on one
release test ELF, scale1, 39x154, 4095-byte reads, five internal passes. No
pilot, retries, exclusions, optional stopping, score pooling or rescue arm.
The printed rates remain best-of-five, not five independent samples; CPU and
wall passes minimized separately by the existing harness.
