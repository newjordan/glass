## New question and implemented mechanism

Rather than another width-cache, decoder or parser rewrite, this experiment
changes zero-width handling in `Watch::put_row`. A mark previously ends the row
lane and goes through the caller's `input` fallback. The candidate retains the
index of a base only after a positive-width write by the **same invocation**.
A subsequent mark attaches to that index using the unchanged
`Cell::push_zerowidth`, invalidates the uniform span, updates held-scalar state,
and continues decoding without advancing the cursor or the positive-cell drain
count. Entry marks without a locally written base still fall back. A wide
base's index is its first cell, not its spacer. A final-column base can receive
marks while wrap is pending.

This differs from an unrestricted inline-mark or saved-row continuation idea:
it does not infer a base in a stale/lazy prefix and holds no cross-call index.
Earlier generic inline-mark plumbing was discussed/deleted in historical
reports; this is an explicit, retained implementation with that restricted
ownership proof and measured opportunity accounting. Cell representation,
mark cache/COW/cap policy, Unicode width policy, UTF-8 validation, parser, and
reader/transport remain unchanged. `candidate.patch` and the four source files
per arm bind the exact proposal. Both arms include the same new targeted test;
the test is retained as a snapshot, not installed in the restored runtime tree.

## Prospective method, correctness and fixed endpoint

`protocol.json` was written before the builds and timing. No pilot, rescue
variant, exclusion, optional stopping, second series or pooled earlier score
was used. Each optimized release test executable was built by the existing
`bench/build-engine-arm.py`, with fresh compiler receipts for vte,
alacritty_terminal and glass. The only runtime-source difference between
measured arms is the retained engine patch. The helper's first candidate
check found an ambiguous `None`; specifying `Option<usize>` fixed compilation
before measured executable construction.

Each arm passed:

* 384 terminal tests (11 ignored), including the new local-mark regression;
* 1,728 targeted scenarios, independently logged: narrow/wide bases, entry
  marks, pending wrap, disabled wrap, recycled rows, repeated marks exceeding

These are differential checks on their defined inputs, not a proof of complete
terminal/Unicode compatibility or correctness of the shared oracle.

## Did the intended path actually run?

After all timing ended, a separate third executable instrumented the candidate
only. It is never used for rates. On one pass of the same Unicode generator
(scale 2, 154x39, 4095-byte reads), a direct scalar scan found 507,568 zero-width
scalars in 33,554,476 bytes. Counters recorded:

* **490,113 local mark commits (96.56105%)**;
* **17,455 zero-width fallback inputs (3.43895%)**;
* exact equality `local + fallback == independently scanned expected`.

The direct scan uses Glass's same width policy and warms its cache. This is an
opportunity/accounting check, not independent Unicode policy validation or a
cold-cache/cost experiment. The counted build changes layout and adds atomic
operations. Do not infer its run time, cycle share, or causal attribution.
Counts establish that the new path was exercised heavily; they rule out the
simple explanation "the lane never ran" for this screen's failure.

## Static tradeoff and descriptive uncertainty

Exact ELF disassembly shows `print_utf8` grew from **8,524 bytes / 1,967
instructions** to **9,905 bytes / 2,293 instructions**. Its entry moved from
`0x2625a0` to `0x262620`; both have 32-byte alignment. `Engine::apply` retained
9,774 bytes / 2,048 instructions with identical relocation-masked instructions,
but its entry also moved by 128 bytes. These static facts do not isolate
front-end effects, register pressure, branch behavior or general code layout as
the cause. There is no dynamic instruction/cycle attribution.

`dispersion.py` is explicitly post-hoc descriptive, not a revised acceptance
rule. It reproduces all 12 ratios without exclusions. Unicode ranges from
.90829 to 1.17186. Six-pair order-stratum medians are .99208 when control is
launched first and 1.07381 when candidate is first. This difference does not
prove order caused the dispersion: strata have only six observations and are
confounded with block/time. An order-statistic median interval [.96740,
1.08327] has 96.14258% nominal coverage only under independent continuous
sampling; that assumption is unestablished on this shared host. The interval
includes both a loss and an improvement; it cannot support equivalence,
noninferiority or competitive superiority.
