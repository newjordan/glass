2. New distinction: parser CPU-bound versus reader/handoff-heavy regimes

Boundary-only medians, per-thread CPU runtime / DA1 wall time:
                      parser        reader       parser voluntary switches
 ASCII                .5313         .8655        1216
 Unicode              .9859         .2381          12
 truecolor            .9879         .2723          13
 cursor motion        .9890         .2451          10
 scroll region        .5230         .8894         835.5
 TUI frames           .9895         .2840          11

Thread CPU is concurrent, not additive fractions of one budget. Off-CPU
residual cannot distinguish runnable, blocked, frequency/cache or SMT causes.
The producer payload write spans a median 99.7-99.9% of pass wall time across
all workloads; this is backpressure and not 99% Python execution CPU.
Sampled task states are consistent with these regimes but not causal traces.

New concrete counterexample to a scheduler-wait-only explanation:
The slowest boundary Unicode pass (tput-edges-6, pass 1) took 133.915 ms wall
and 131.076 ms parser CPU, with two involuntary context switches. Fastest
Unicode wall was 59.783 ms and median 63.036 ms. The reproduced excursion
has substantially increased on-CPU parser cost, not merely a long off-CPU
pause. It does NOT identify frequency, caches, SMT, data dependency or other
causes. Earlier >10x ASCII excursions did not recur, so they remain undiagnosed.

3. New exact-binary leaf CPU profiles

perf was absent, perf_event_paranoid=2, tracing inaccessible. Instead a small
own-process Linux/x86-64 LD_PRELOAD DSO arms a thread CPU-time signal timer on
the named current thread. It stores only RIP, timestamp and optional call
label in fixed lock-free storage, not application data or environment. It is
not part of Glass release and introduces real overhead. The Python child is
excluded by exact executable-path filtering. Output refuses overwrite.

Six sessions: three parser plus three reader. All complete, 18 passes each.
Symbolizer matches pass windows and ELF mapping offsets through LOAD segments,
requires a containing symbol, retains unknown addresses. Exact ELF hashes bind
symbolization; replays need those ELF files at their recorded paths.

Unicode parser: 435/547 delivered matched samples (79.5%) in
Watch::print_utf8. Across sessions: 144/181, 145/181, 146/185.
ASCII print_run: 36/142 (25.4%); scroll region print_run: 23/85 (27.1%).
No inclusive stack or source-line claim. Requested 100-us thread timer
produced ~1-ms parser sample spacing; delivery is coarse and can alias.

Most reader samples land at libc 0xa08f2 (__syscall_cancel_arch_end), shared
by cancellation-aware syscalls. This cannot independently identify poll/read.
We retained the exact disassembly rather than guessing a nearest export.

These sample counts are not independently randomized 100-us CPU observations.
