NEW FINDING: AN UNRELATED TRUNCATED TAIL DELETES A SURVIVING PICTURE
Start at 4 rows x 10 columns with nine retained history rows. Write four full
10-character visible rows. Put marker M and an actual Kitty picture at row 0,
column 3; put cursor on row 3. Use Session's resize -> take_reflow -> intake.reflow
-> set_scrolled_primary order for 8x5, then 4x10.
At 8x5 the picture is still (0,3). At 4x10 text M remains (0,3), but there are ZERO
placements. Shipping control's desired-invariant test FAILS (exit 101, one test),
with exact grid, Reflow and placement traces in control-round-trip.log.

The first resize splits each full line into 5+5. On return, the last logical
line is truncated from ten characters to five; the first three logical lines
survive at length ten. motion::align_content requires a complete length-sequence
match. A mismatch at that unrelated tail makes the whole match fail, leaving no
mapping for the intact first marker. This is not text-content matching: GridSnap
stores occupied lengths/wrap flags, not character identities.

A separate pure matcher characterization isolates the mechanism without parser,
grid resize, or picture protocol: old content lengths [10,10,10,10] mapped to
[10,10,10,5] produce map_anchor(9,3)=None. Changing ONLY that final 5 to 10
preserves the exact same anchor as (9,3). The end-to-end characterization confirms
the actual intake loss, while this one-field sensitivity isolates the matcher
limitation. Both are deliberately named defect characterizations, not correctness
tests. Replace/remove their broken-behavior assertions when the real fix lands.
